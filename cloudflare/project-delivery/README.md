# CommandCenter Project Delivery Gateway v1 (source candidate)

**Status: SOURCE IMPLEMENTED, 7/7 OFFLINE TESTS; NOT INSTALLED, NOT ADMITTED, NOT HOSTED.** This is product-neutral and intentionally holds **zero Cloudflare administration credentials**. It is not the protected `reference-release-*` controller or the Pi signer and cannot create Workers, modify DNS/Access, mint API tokens, or run commands. Preserve these separations.

## Purpose and routing

The previously proven ordinary `SlenderIQ` `shared-compute-worker-factory` has `ordinary_worker.create` and `existing_worker.editor_token.issue` contracts. It cannot administer the separate Shared Compute Neutral Authorization account. Because that account owns `lifelatelycounseling.com`, ordinary account factory credentials must **never** be stretched into the neutral account.

Instead, provision **one** unprivileged `cc-project-delivery` Worker in the domain-owning neutral account, with only a dedicated R2 bucket and SQLite Durable Object binding. It can serve any subsequently registered exact `project.apps.lifelatelycounseling.com` hostname and optionally the already owner-protected `studio.lifelatelycounseling.com` without issuing a token for each release. Protect the controller endpoint at `release.apps.lifelatelycounseling.com` with a separate owner-only Cloudflare Access app; users of each site need an exact signed Cloudflare Access app JWT with the audience recorded in its active manifest. Never attach wildcard routes at `*.lifelatelycounseling.com/*` because this would risk HAOS and gateway-ops. A more restrictive `*.apps.lifelatelycounseling.com/*` route and wildcard Access application require independent owner admission and collision review. For `studio.lifelatelycounseling.com`, route/Worker collision with `incomeengine-3d-studio` must be independently verified before any replacement or attachment.

## Bounded API after separate first installation

- `POST https://release.apps.lifelatelycounseling.com/v1/prepare`: JSON manifest `commandcenter.cloudflare.project_delivery.v1`, fresh lowercase 32-hex request and release IDs, `project_id`, exact whitelisted hostname, exact owner Access `access_aud`, <=300-second expiry, 1-128 files with absolute allowed paths, exact SHA-256 and bytes. Max file 20 MB, total 120 MB; no remote code execution, paths escaping projects, arbitrary API URLs or credential issuance.
- `PUT /v1/upload/<project>/<release_id>/<sha256>`: owner-signed Cloudflare Access assertion and same-origin header required, binary bytes must exactly match preapproved manifest hash and size. Stored under content-addressed R2 names. Private source/model bytes are NEVER committed to a public GitHub repo or copied into public Actions logs/artifacts.
- `POST /v1/activate`: fresh signed owner request, manifest and every R2 object must be present; a Durable Object per site atomically compares the expected predecessor, records the active release and permanently rejects reused request IDs. This provides a versioned, single-use release switch and rollback through a new explicitly authorized activation, never deletion of old content.
- `GET`/`HEAD` on approved site host: signed per-site Access JWT and exact owner allowlist required for **each file**; serves only the active approved manifest's immutable R2 objects with private no-store and restrictive CSP. No anonymous public file URLs, `.workers.dev` or preview routes.

Privileged publishing is deliberately disabled by `RELEASE_ENABLED=0`. Initial operator-authenticated publication is the first release lane. **Unattended CommandCenter authorization is not yet installed**: it needs a separately admitted, single-purpose grant verifier/queue consumer, not a standing all-account Cloudflare bearer or reusable broker signer masquerading as another key role. The package supplies no magic ChatGPT API transport by itself.

## Two distinct future project classes

- **Static asset sites, 3D viewers, downloadable catalogs, SPAs**: one fixed neutral delivery Worker; new project content is registered by a typed project manifest/release and published into its own immutable R2 namespace. No additional Worker/token per project; any new custom hostname outside `*.apps` still requires an independently authorized route/Access binding.
- **Independent executable Workers / scheduled business logic**: use the **existing original ordinary-account factory** with bounded create and scoped-Editor issuance, after its live enablement and neutral DENY readback. It must not be granted access to neutral broker/signer or the counseling zone. If a workload insists on a new individual Worker inside the neutral account, this architecture does NOT silently provide product-level Workers Admin; a separate protected, account-isolated first admission is required.
